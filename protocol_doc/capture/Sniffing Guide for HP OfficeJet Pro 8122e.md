# Intercepting HP "Scan to Computer" for  Protocol using mitmproxy & ProxyBridge

This guide explains how to proxy and capture network traffic generated by the HP "Scan to Computer" application on Windows.

## 🛑 Problem Statement

On certain printer models, such as the **HP OfficeJet Pro 122e**, standard trickery like redirecting traffic using IPv4-to-IPv6 translation does not work because the printer responds to IPv6 requests with `404 Not Found` errors.

To bypass this restriction and inspect the plain/encrypted HTTP(S) protocol traffic, we use **ProxyBridge** to transparently route application traffic targeting the printer's IP address into **mitmproxy** (`mitmweb`).

## 🛠️ Prerequisites

1. **mitmproxy / mitmweb**: Download the binary executable release (`mitmweb.exe`) from [mitmproxy.org](https://mitmproxy.org/).

2. **ProxyBridge**: Download and install [ProxyBridge by InterceptSuite](https://github.com/InterceptSuite/ProxyBridge).

## 🚀 Step-by-Step Setup

### Step 1: Launch mitmweb

Run `mitmweb` with a specific listening host and port via Command Prompt / PowerShell:

```
mitmweb --web-host 127.0.0.1 --listen-port 8443 --ssl-insecure

```

This will spin up:

* **Proxy Server:** `127.0.0.1:8443`

* **Web UI:** Automatically opens in your default browser (usually at `http://127.0.0.1:8081`) to display captured flows.

### Step 2: Configure Proxy Server in ProxyBridge

1. Launch **ProxyBridge**.

2. Navigate to **Proxy Settings** (or Add Proxy Server).

3. Fill in the server details:

   * **Name:** `mitm`

   * **Address:** `127.0.0.1`

   * **Port:** `8443`

   * **Protocol:** `HTTP`

   * **Options:** Enable **"Let proxy resolve DNS (send hostname)"**

4. Save the configuration.

> 💡 *Optional:* Run **Proxy Checker (Proxy Test)** within ProxyBridge to verify that `127.0.0.1:8443` responds properly (e.g., testing connection to `www.google.com:80`).

### Step 3: Define Routing Rules in ProxyBridge

To capture traffic without creating an infinite proxy loop, you must define rules carefully.

#### Rule 1: Prevent Proxy Loop (Bypass Rule)

Add a direct rule so `mitmweb`'s own traffic bypasses ProxyBridge:

* **Rule Name:** `Bypass mitmweb`

* **Applications:** `mitmweb.exe`

* **Target Hosts:** `*`

* **Target Ports:** `*`

* **Protocol:** `BOTH` (TCP/UDP)

* **Action:** `Direct`

#### Rule 2: Redirect HP Printer Traffic

Add a rule to capture traffic aimed at the printer's local IP address:

* **Rule Name:** `ProxyBridge Rule`

* **Applications:** `*` (or specify the HP application process)

* **Target Hosts:** `<YOUR_PRINTER_IP>` *(e.g., `192.168.2.199`)*

* **Target Ports:** `*` *(or specific ports like `443`)*

* **Protocol:** `TCP` ⚠️ *(Do NOT select UDP; mitmproxy does not support UDP proxying and forcing UDP through it may break HP application operations/discovery)*

* **Action:** `mitm HTTP 127.0.0.1:8443`

## 🔍 Capturing & Analyzing Flows

1. Ensure both **mitmweb** and **ProxyBridge** are running with the rules enabled.

2. Trigger the "Scan to Computer" action from your HP app or printer front panel.

3. Switch to your browser showing the **mitmweb UI**.

4. You will now see all HTTP/HTTPS endpoints, headers, payloads, and protocol messages exchanged between the PC and printer in real-time.

## 📌 Important Notes

* **SSL/TLS Certificates:** If HTTPS traffic is intercepted, install the mitmproxy CA certificate (`mitmproxy-ca-cert.cer` generated in `~/.mitmproxy/`) into the Windows **Trusted Root Certification Authorities** store if the HP application performs standard SSL certificate validation.

* **Protocol Selection:** Stick to **TCP** when filtering in ProxyBridge to prevent breaking mDNS or SSDP network discovery protocols that rely on UDP.
